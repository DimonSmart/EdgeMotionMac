# IDD-0006.adr-private-input-public-output

## Status

Accepted

## Context

Продукту нужны system-wide per-finger contacts при работе других приложений. Предоставленное ТЗ выбирает MultitouchSupport для этой границы и обычные Quartz events для продолжения курсора. Private ABI остаётся неподдерживаемым Apple и требует собственной квалификации. Принятие целевого подхода не означает, что осуществимость уже проверена.

## Decision

Целевой путь — raw contacts через private MultitouchSupport → независимый детерминированный движок → публичный CGEvent output. Неподдерживаемая часть локализуется на input boundary; нормативные ограничения реализации принадлежат инженерным правилам проекта.

Продукт — non-sandboxed user-space utility с direct distribution. Требования безопасности и поставки принадлежат IDD-0004; gate аппаратной осуществимости — IDD-0007.

### Подтверждённые технические решения границы input

- Framework загружается динамически, а отсутствие требуемого symbol, устройства, корректного запуска или валидного кадра оставляет функцию выключенной без synthetic output.
- Callback private framework рассматривается как `int32_t`-возвращающий и всегда возвращает `0`, чтобы не вмешиваться в системное распознавание жестов.
- Reverse-engineered контакт декодируется только внутри C boundary из 96-байтового opaque layout; Swift получает лишь device identity, `pathIndex`, `fingerID`, нормализованные координаты, timestamp, фазу и sequence.
- `MTDeviceStart` проверяется как операция со статусом. Исходный список устройств удерживается весь срок короткой input-сессии, поскольку его элементы не переходят в собственность вызывающего кода.
- Для continuity используются оба наблюдаемых идентификатора: замена контакта подтверждается только когда меняются и `pathIndex`, и `fingerID`. Это предотвращает ложное подавление от transient изменения одного из них.
- Public cursor output допускается только после валидации frame и проверки Accessibility. Private callback не публикует Quartz events напрямую.

Эти решения описывают текущую неподдерживаемую границу, а не публичный контракт Apple и не подтверждают все OS/hardware combinations.

## Evidence and provenance

Первоначальная проверка выполнялась отдельным короткоживущим аппаратным harness (`EdgeMotionHardwareDiagnostic`). Подробный протокол, числовые результаты и границы подтверждённой совместимости сохранены в IDD-0007. По окончании исследования отдельный executable и его экспериментальный lifecycle были удалены из актуальной сборки; исходный код остаётся доступным в истории Git.

Рабочий ввод использует `EdgeMotionInputBridge` (C boundary с private API) и `EdgeMotionInputCore` (контакты, валидация кадров и Quartz output). Эти компоненты не являются удалённым экспериментом: они входят в пользовательское приложение. Наличие рабочего runtime не отменяет квалификацию каждой OS/hardware combination.

## Alternatives Considered

- Public NSTouch пригоден для собственного окна/diagnostics, но в источнике не рассматривается как полноценный global input backend.
- IOHIDManager полезен для enumeration и device monitoring; в источнике не выбран основным путём Apple raw contacts. Сторонние HID-трекпады остаются экспериментальным направлением.
- DriverKit virtual HID усложняет deployment и не решает сам по себе raw Apple input; исключён из V1.
- Kext, root daemon и SIP changes исключены по security/deployment ограничениям.
- Постоянный cursor warp не выбран: продолжение должно публиковаться как обычные mouse/drag events.

## Consequences

Apple может изменить ABI, symbols или доступность framework. Поддержку необходимо подтверждать на каждой OS/hardware combination; при несовместимости функция безопасно отключается. Direct distribution и notarization не устраняют риск private API. Public-only оконный demo не является заменой system-wide продукта.

Lifecycle unregister/reconnect, sleep/wake и повторное создание device handles требуют отдельной аппаратной квалификации до заявления production-support. Текущий короткоживущий запуск не является доказательством безопасности этих сценариев.
