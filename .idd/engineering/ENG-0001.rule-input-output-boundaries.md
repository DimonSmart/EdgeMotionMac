# ENG-0001.rule-input-output-boundaries

## Rule

Основной Apple raw-contact backend использует MultitouchSupport. Private ABI локализован в одном небольшом C/Objective-C bridge; private structs не передаются за его границу в Swift. Остальные части используют собственную стабильную модель кадров. Cursor output использует публичные CoreGraphics/Quartz CGEvent, а не постоянный CGWarpMouseCursorPosition.

## Applicability

Conditional

## Applies when

- Изменяется input backend, граница private framework, модель контактов или cursor output.

## Rationale

Исходное ТЗ явно отделяет единственную private часть — чтение raw contacts — от остальной системы. Изоляция ограничивает область изменений при несовместимости ABI. Обоснование выбора описано в IDD-0006.

## Guidance

Внутренняя модель передаёт device identity, finger identity, normalized position, timestamp, phase и frame sequence. Velocity и аппаратные pressure/geometry поля могут быть необязательными. Примеры reverse-engineered структур не принимаются за подтверждённый layout. Framework/symbol/ABI checks должны позволять безопасное отключение. Динамическая загрузка — допустимый предложенный приём, а не обязательный способ linkage.

IOKit/IOHID применяется для enumeration, identification и device monitoring; он не подменяет основной Apple raw-contact backend без отдельного подтверждённого решения. Output сохраняет mouseMoved/leftMouseDragged semantics и modifier/button context согласно продуктовым требованиям.

## Verification

За пределами bridge отсутствует зависимость от private structs и ABI layout. Некорректные или недоступные входные данные не приводят к output. Аппаратные доказательства подтверждают интерпретацию кадров, а output использует публичные CGEvent с правильным контекстом.
